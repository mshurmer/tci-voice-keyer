# Milestone 4 - Generated 1 kHz TX tone

This milestone builds directly on the proven Milestone 3 TX_CHRONO/silence path.

## Purpose

Prove that non-zero float32 audio samples generated by the application reach the Thetis TCI transmit-audio path correctly.

## Guardrails

- Receiver/transceiver 0 only.
- Requires `tx_enable:0,true;`.
- Refuses to key unless Thetis reports receiver 0 modulation as `USB`.
- Requires exact operator confirmation `TONE`.
- 3-second countdown before TX.
- TX duration approximately 750 ms.
- Generated tone is 1 kHz at -20 dBFS peak amplitude.
- Uses the proven 48 kHz / float32 / stereo / 512-samples / 100 ms buffering negotiation.
- Every TX_CHRONO packet is validated before a TX_AUDIO_STREAM packet is built.
- Unkey command is sent after the timed TX window and cleanup attempts to force RX if necessary.

## Run

```powershell
git fetch
git checkout feature/test-tone
git pull

dotnet run --project src/TciVoiceKeyer.ToneDiagnostic -- ws://127.0.0.1:50001/
```

Before entering `TONE`, confirm Thetis is in USB mode, MOX is off, and the radio is connected to a dummy load or otherwise configured so a brief transmission is safe.

## Expected result

The program should receive type 3 TX_CHRONO packets, respond with type 2 TX_AUDIO_STREAM packets containing the generated sine wave, then send `trx:0,false;` and observe `trx:0,false;` from Thetis.

A successful console run ends with:

```text
*** Milestone 4 candidate success: generated tone samples supplied and RX confirmed. ***
```

The operator should also confirm that the tone is visible/audible in an appropriate monitor path and that MOX releases automatically.
